# نَبّهني — لا تنسَ شيئًا بعد اليوم

منصّة ذكية لإدارة **المهام والمواعيد والتذكيرات والعادات**، بواجهة عربية كاملة (RTL)،
تعمل كتطبيق ويب وتطبيق مثبّت على الجوال (PWA)، وجاهزة للتحول إلى تطبيق iOS/Android
عبر Capacitor دون إعادة بناء.

> **جرّبها فورًا:** `npm install && npm run setup && npm run dev`
> ثم سجّل الدخول بـ `demo@nabbihni.app` / `Demo12345`

## التشغيل في ٣ دقائق

المتطلب الوحيد: **Node.js 22.5 أو أحدث** (نستخدم `node:sqlite` المدمج).

```bash
npm install       # تثبيت الحزم
npm run setup     # إنشاء قاعدة البيانات + بيانات تجريبية واقعية
npm run dev       # http://localhost:3000
```

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | خادم التطوير |
| `npm run build` / `npm start` | بناء وتشغيل نسخة الإنتاج |
| `npm run db:push` | إنشاء/تحديث جداول قاعدة البيانات |
| `npm run db:seed` | تعبئة بيانات تجريبية |
| `npm run db:reset` | حذف كل شيء والبدء من جديد |
| `npm test` | تشغيل ١٢٩ اختبارًا آليًا على الـ API والصفحات |
| `npm run typecheck` | فحص الأنواع |

(٢٥ مهمة، ٥ مواعيد، ٥ عادات بسجلّ ٦٠ يومًا، إشعارات، وتصنيفات جاهزة)

## لماذا هذه التقنيات؟

| الطبقة | الاختيار | السبب |
|---|---|---|
| الإطار | **Next.js 15 (App Router)** | خادم وواجهة في مشروع واحد، تصيير من الخادم يجعل أول رسم سريعًا، ومسارات API مدمجة. |
| اللغة | **TypeScript** بوضع `strict` | يمنع فئة كاملة من الأخطاء قبل التشغيل، ويجعل إعادة الهيكلة آمنة. |
| الواجهة | **React 19 + Tailwind CSS** | مكوّنات قابلة لإعادة الاستخدام + نظام تصميم موحّد بمتغيّرات CSS يدعم الوضع الليلي بتبديل صنف واحد. |
| قاعدة البيانات | **SQLite عبر `node:sqlite`** | مدمج في Node 22، صفر تبعيات أصلية، ملف واحد — يشتغل فورًا على أي جهاز. مكتوب بـ SQL قياسي لينتقل إلى PostgreSQL بتبديل ملف واحد. |
| التحقق | **Zod** | مخطط واحد يخدم الخادم والواجهة، ورسائل خطأ عربية لكل حقل. |
| الجلسات | **jose (JWT) + bcryptjs** | كوكي HttpOnly موقّع + سجل جلسة في قاعدة البيانات يسمح بالإبطال الفوري. |
| الإشعارات | **web-push (VAPID)** | معيار الويب المفتوح، يصل حتى والتطبيق مغلق. |
| الرسوم | **SVG يدوي** | صفر كيلوبايت إضافية، وتحكّم كامل في الاتجاه (RTL) والألوان الآمنة لعمى الألوان. |

**لماذا لا ORM؟** كل الاستعلامات تمر عبر واجهة واحدة (`db.all/get/run`) في
`src/server/db/client.ts`. هذا يعطي وضوحًا كاملًا في الاستعلامات (مهم للأداء
والفهارس) ويجعل استبدال المحرّك بـ PostgreSQL تعديلًا في ملف واحد. ولمن يفضّل
Prisma، يوجد مخطط مكافئ جاهز في `docs/postgres-prisma-reference.prisma`.

## المعمارية

الفصل صارم: **كل طبقة قابلة للاستبدال دون لمس البقية.**

```
src/
├─ app/                       المسارات (Next.js App Router)
│  ├─ page.tsx                الصفحة الرئيسية التسويقية
│  ├─ (auth)/                 تسجيل الدخول، إنشاء حساب، استعادة، تفعيل البريد
│  ├─ (app)/                  الصفحات المحميّة (لوحة التحكم، المهام، التقويم…)
│  └─ api/                    ٢٨ مسار REST
│
├─ components/
│  ├─ ui/                     مكوّنات أساسية (أزرار، نوافذ، حقول، تنبيهات)
│  ├─ app/                    مكوّنات التطبيق (لوحة التحكم، المهام، المساعد…)
│  └─ marketing/              مكوّنات الصفحة الرئيسية
│
├─ lib/                       كود مشترك آمن للعميل (أنواع، تواريخ، تحقق، عميل API)
│
├─ server/                    كود الخادم فقط (محميّ بـ 'server-only')
│  ├─ db/                     الاتصال + المخطط + توليد المعرّفات
│  ├─ auth/                   كلمات المرور، الجلسات، الرموز المؤقتة
│  ├─ api/                    أدوات المسارات (استجابات، أخطاء، حدّ المعدّل)
│  ├─ repos/                  الوصول للبيانات (مهام، مواعيد، عادات، …)
│  └─ services/               منطق الأعمال
│     ├─ agenda.ts            دمج المهام والمواعيد في جدول واحد
│     ├─ analytics.ts         حساب الإحصائيات
│     ├─ reminder-engine.ts   محرّك إرسال التذكيرات
│     ├─ push.ts              طبقة Web Push
│     ├─ email.ts             طبقة البريد (console / Resend / أي مزوّد)
│     └─ ai/                  طبقة الذكاء الاصطناعي (محلّي / LLM خارجي)
│
└─ middleware.ts              حارس المسارات المحميّة
```

**قواعد لا تُكسر:**

1. مكوّنات الواجهة لا تستدعي قاعدة البيانات — تمر عبر `src/lib/api-client.ts`.
2. المستودعات (`repos/`) لا تعرف شيئًا عن HTTP.
3. الخدمات الخارجية (بريد، إشعارات، ذكاء اصطناعي) خلف واجهات — استبدال المزوّد
   لا يمسّ التطبيق.
4. كل استعلام مقيَّد بـ `user_id`. لا استثناء.

## قاعدة البيانات

١٨ جدولًا مع علاقات وفهارس كاملة — التفاصيل في [`docs/DATABASE.md`](docs/DATABASE.md).

```
users ─┬─ user_settings (1:1)
       ├─ sessions            جلسات قابلة للإبطال
       ├─ verification_tokens رموز التفعيل وإعادة التعيين
       ├─ workspaces ── workspace_members     (جاهز للمشاركة والفرق)
       ├─ categories ─┬─ tasks ─┬─ reminders
       │              │         ├─ attachments
       │              │         └─ tasks (تكرار: أب/ابن)
       │              ├─ events ── reminders
       │              └─ habits ─┬─ habit_logs
       │                         └─ reminders
       ├─ notifications
       ├─ push_subscriptions
       └─ ai_conversations ── ai_messages
```

**قرارات تصميمية:**

- كل الأوقات **UTC بصيغة ISO-8601**؛ العرض بتوقيت المستخدم. مفاتيح الأيام
  (`YYYY-MM-DD`) تُحسب دائمًا بتوقيت المستخدم لا الخادم.
- `reminders.trigger_at` وقت مطلق محسوب مسبقًا مع فهرس `(status, trigger_at)`،
  فيصبح استعلام «ما المستحق الآن؟» فهرسيًا بحتًا.
- `habit_logs` عليه `UNIQUE(habit_id, date)` — يستحيل تسجيل اليوم مرتين.
- `ON DELETE CASCADE` في كل مكان: حذف الحساب يمحو كل أثره فورًا.

### الانتقال إلى PostgreSQL

1. بدّل الاتصال في `src/server/db/client.ts` بـ `pg` أو `postgres.js`.
2. طبّق `schema.sql` مع التحويلات: `TEXT (ISO)` → `TIMESTAMPTZ`، `INTEGER (0|1)` → `BOOLEAN`.
3. لا شيء آخر يتغيّر — المستودعات تستخدم SQL قياسيًا ومعاملات موحّدة.

## واجهة الـ API

REST بشكل استجابة موحّد، وأخطاء عربية، وتحقق Zod على كل مدخل.

| المجموعة | المسارات |
|---|---|
| المصادقة | `POST /api/auth/{register,login,logout,forgot-password,reset-password,verify-email,change-password}` · `GET /api/auth/me` |
| المهام | `GET,POST /api/tasks` · `GET,PATCH,DELETE /api/tasks/[id]` · `POST /api/tasks/[id]/complete` · `POST /api/tasks/[id]/reschedule` |
| المواعيد | `GET,POST /api/events` · `GET,PATCH,DELETE /api/events/[id]` |
| العادات | `GET,POST /api/habits` · `GET,PATCH,DELETE /api/habits/[id]` · `POST /api/habits/[id]/log` |
| التصنيفات | `GET,POST /api/categories` · `PATCH,DELETE /api/categories/[id]` |
| الإشعارات | `GET,DELETE /api/notifications` · `POST,DELETE /api/notifications/[id]` · `POST /api/notifications/read-all` · `GET /api/notifications/due` |
| Push | `GET /api/push/vapid` · `POST,DELETE /api/push/subscribe` · `POST /api/push/test` |
| أخرى | `GET,PATCH /api/settings` · `GET,PATCH,DELETE /api/profile` · `GET /api/analytics` · `GET /api/search` · `GET /api/suggestions` |
| الذكاء الاصطناعي | `POST /api/ai/parse` · `POST /api/ai/create` · `GET /api/ai/status` |
| المجدول | `GET,POST /api/cron/dispatch` (محميّ بـ `CRON_SECRET`) |

شكل الخطأ الموحّد:

```json
{ "error": "bad_request", "message": "البيانات المُرسلة غير صالحة.",
  "details": { "title": "اسم المهمة مطلوب" } }
```

## نظام التذكيرات

ثلاث طبقات متكاملة، كل واحدة تعمل ولو تعطّلت التي فوقها:

1. **داخل التطبيق** — `ReminderWatcher` يسأل `/api/notifications/due` كل ٣٠ ثانية
   (ويتوقف تلقائيًا عندما تكون الصفحة مخفية). يعمل دائمًا بلا أي إعداد.
2. **إشعار المتصفح** — عبر Notification API، يعمل حتى في تبويب آخر.
3. **إشعار دافع (Web Push)** — يصل والتطبيق مغلق تمامًا، بعد ضبط مفاتيح VAPID.

**التذكير الذكي:** لكل مهمة حتى ٦ تذكيرات (قبل يوم، ثم ساعة، ثم ١٠ دقائق…)،
مع **ساعات هدوء** تُسكت الإشعارات في أوقات نومك.

**عدم التكرار:** حالة التذكير تتغيّر إلى `sent` في نفس المعاملة، فلا يُرسل مرتين
حتى لو تزامن المسارَان.

**إعادة الجدولة الذكية:** عند تأخّر مهمة، يقترح النظام ٣ أوقات مبنية على جدولك
الفعلي (يتجنّب الساعات المزدحمة)، أو تختار وقتًا مخصصًا.

### تفعيل الإشعارات الدافعة

```bash
npm run generate:vapid     # ثم انسخ المفتاحين إلى .env
```

للتشغيل والتطبيق مغلق، استدعِ المجدول كل دقيقة:

```jsonc
// vercel.json
{ "crons": [{ "path": "/api/cron/dispatch", "schedule": "* * * * *" }] }
```

```bash
# أو من خادمك
* * * * * curl -H "Authorization: Bearer $CRON_SECRET" https://your-domain/api/cron/dispatch
```

## المساعد الذكي

اكتب بلغتك الطبيعية → مسودّة كاملة → تراجعها → تُحفظ.

```
«ذكرني أذاكر الفصل الثالث يوم الخميس الساعة ٧ مساءً»
  ↓
العنوان: مذاكرة الفصل الثالث · التاريخ: الخميس · الوقت: ٧:٠٠ م
التذكير: قبل ١٠ دقائق · التصنيف: الدراسة
  ↓
[إنشاء]  [تعديل]
```

يفهم: الأيام (`الخميس`، `بكرة`، `بعد يومين`)، الأوقات (`٧ مساءً`، `3:30 م`،
`العصر`)، التكرار (`كل أحد وثلاثاء وخميس`، `كل يومين`)، الأولوية (`عاجل`، `مهم`)،
المدة (`لمدة ساعة`)، والتذكير (`ذكرني قبل ساعة`) — ويطبّع الهمزات والتاء المربوطة
والأرقام العربية-الهندية تلقائيًا.

**عند نقص المعلومات يسأل بدل أن يخمّن:**
«متى تريد أن أذكّرك بـ‹اتصل بأحمد›؟»

**يعمل بلا مفاتيح** عبر محلّل قواعدي داخلي. لتفعيل نموذج لغوي:

```env
AI_PROVIDER=anthropic     # أو openai
AI_API_KEY=sk-...
AI_MODEL=claude-sonnet-4-5
```

الواجهة (`AiProvider` في `src/server/services/ai/index.ts`) لا تتغيّر، وعند فشل
المزوّد الخارجي يعود النظام تلقائيًا للمحلّل المحلي فلا تتعطّل الميزة أبدًا.

## PWA وتطبيقات الجوال

- **Web App Manifest** مع أيقونات، اختصارات سريعة، ووضع `standalone`.
- **Service Worker**: أصول ثابتة (cache-first)، صفحات (network-first + صفحة
  «لا يوجد اتصال»)، ولا يُخزَّن أي طلب `/api` أبدًا.
- **دعوة تثبيت** ذكية تظهر بعد أن يستقر المستخدم، ولا تتكرر بعد الرفض.
- **تصميم Mobile-First**: تنقّل سفلي، زر إضافة عائم، نوافذ تتحول إلى أوراق سفلية.

### التحويل إلى iOS و Android

المشروع لا يعتمد على أي واجهة خاصة بالمتصفح خارج طبقة رفيعة معزولة، لذا:

```bash
npm i -D @capacitor/cli && npx cap init
npx cap add ios && npx cap add android
```

ثم وجّه Capacitor إلى نسخة الويب المستضافة (`server.url`)، أو صدّر واجهة ثابتة
مع إبقاء الـ API على خادمك. كل منطق الأعمال في `server/` يبقى كما هو، وطبقة
`api-client.ts` هي نقطة التبديل الوحيدة.

## الأمان

| الإجراء | التنفيذ |
|---|---|
| تجزئة كلمات المرور | bcrypt بـ ١٢ جولة، ولا تُخزَّن أبدًا كنص |
| الجلسات | JWT موقّع (HS256) في كوكي `HttpOnly` + `SameSite=Lax` + `Secure` في الإنتاج |
| الإبطال الفوري | كل جلسة لها سجل في قاعدة البيانات؛ تغيير كلمة المرور يبطل كل الجلسات |
| الرموز المؤقتة | تُخزَّن مجزّأة SHA-256، وتُستهلك مرة واحدة، وتنتهي تلقائيًا |
| عزل البيانات | كل استعلام مقيَّد بـ `user_id` — محاولة الوصول لعنصر غيرك تُعيد ٤٠٤ |
| التحقق من المدخلات | Zod على كل مسار، مع حدود طول ونطاق لكل حقل |
| حقن SQL | استعلامات مُعامَلة (parameterized) حصراً، بلا استثناء |
| حدّ المعدّل | تسجيل الدخول ١٠/١٥ دقيقة لكل (IP + بريد) و٥٠/ساعة لكل IP؛ وحدود على التسجيل والاستعادة والمساعد الذكي |
| كشف الحسابات | رسائل موحّدة لا تكشف إن كان البريد مسجّلًا |
| ترويسات الأمان | `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` |
| حماية المجدول | `CRON_SECRET` إلزامي على مسار الإرسال |

جميع هذه النقاط مغطّاة باختبارات آلية (القسمان ١٣ و١٦ في `npm test`).

## الأداء

- **تصيير من الخادم** لكل صفحة: البيانات جاهزة في أول رسم، بلا وميض تحميل.
- **تقسيم الكود تلقائيًا** لكل مسار — أثقل صفحة ١٤٩ كيلوبايت أول تحميل.
- **بلا مكتبات رسم**: كل المخططات SVG يدوي (وفّرنا ~٣٠٠ كيلوبايت مقابل Recharts).
- **بلا مكتبة مناطق زمنية**: `Intl` فقط (وفّرنا ~٢٠٠ كيلوبايت مقابل moment-timezone).
- **فهارس مركّبة** على أنماط الاستعلام الفعلية: `(user_id, due_at)`,
  `(user_id, status)`, `(status, trigger_at)`, `(user_id, read_at)`.
- **استعلام واحد لكل شاشة**: البيانات المرتبطة تُجلب دفعةً واحدة (لا مشكلة N+1).
- **`optimizePackageImports`** لأيقونات lucide ودوال date-fns.
- **تحميل كسول** للنوافذ والمكوّنات الثقيلة عبر حدود العميل.

## النشر للإنتاج

### ١) متغيّرات البيئة


## التوسّع المستقبلي

البنية جاهزة لهذه الميزات دون إعادة هيكلة:

| الميزة | ما هو جاهز بالفعل |
|---|---|
| مشاركة القوائم والفرق | جدولا `workspaces` و`workspace_members` بأدوار Owner/Admin/Member، وكل عنصر يحمل `workspace_id` |
| الاشتراكات (SaaS) | حقل `plan` على المستخدم والمساحة + ثوابت الخطط في `constants.ts` |
| المهام الصوتية | مدمج فعليًا في المساعد عبر Web Speech API |
| تذكيرات الموقع | `Permissions-Policy` يسمح بـ geolocation، والتذكير يحمل `channel` قابلًا للتوسعة |
| تذكيرات البريد وواتساب | `channel` في جدول `reminders` + طبقة مزوّدين في `services/email.ts` |
| الخطة اليومية الذكية وتلخيص اليوم | واجهة `AiProvider` تقبل دوال جديدة بلا تغيير في الاستدعاء |
| المرفقات والملاحظات | جدول `attachments` وحقل `notes` يعملان الآن |
| مؤقّت بومودورو والأهداف | حقل `duration_min` وبنية التصنيفات تدعمهما |
| التقويم المشترك | `events.workspace_id` جاهز |
